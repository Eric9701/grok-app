# Internationalization (i18n)

**Rule:** User-visible UI strings must not be hard-coded. Use `t(locale, key)` / `createT(locale)`.

**Catalog fallback is English (`en`).** Supported locales: `zh` (Simplified Chinese), `zh-TW` (Traditional Chinese), `ru` (Russian), and `en`. The Chinese catalogs are complete translations. Russian is an English-backed catalog with explicit Russian overrides, so every key is always safe while translation coverage can grow incrementally. `messages.test.ts` enforces key parity and non-empty values.

**User preference default is `system`** (follow OS UI language). Chinese and Russian Windows / macOS / Linux installs must open in `zh` / `zh-TW` / `ru` without a Settings visit. Unknown OS languages still fall back to English.

## Source locations

| Path | Role |
|------|------|
| `src/i18n/messages/en/` | English catalog; **`en` is the key authority** |
| `src/i18n/messages/zh/` | Simplified Chinese catalog |
| `src/i18n/messages/zh-TW/` | Traditional Chinese catalog |
| `src/i18n/messages/ru/` | Russian catalog; English-backed with translated overrides |
| `src/i18n/messages/index.ts` | Locale registry and canonical catalog map |
| `src/i18n/index.ts` | `t` / `createT` / locale parsing / system-language resolution / types |
| Components | Reference keys only — never hard-code translated UI copy except native language names in the language picker |
| `src-tauri/src/tray_i18n.rs` | Native tray strings (keep in sync with `tray.*` keys; reads `settings.locale`; `"system"` → OS lang) |

## Adding or changing copy

1. Add the key to the **`en` catalog** first (dot keys: `area.action`).
2. **Same PR:** fill `zh` and `zh-TW` with complete translations; add/update the Russian override when the copy belongs to the translated Russian surface.
3. In components: `const tr = useMemo(() => createT(locale), [locale]);` then `tr("sidebar.settings")`.
4. Variables: template `{name}`, call `tr("project.trustFirst", { name: proj.name })`.
5. Do **not** spread `locale === "zh" ? "…" : "…"`; replace leftovers with keys.
6. Product / model names (`Grok 4.5`, `Agent`) may stay English; descriptive UI should be localized where that locale has coverage.
7. Language switch writes `settings.locale` and updates UI immediately.
8. Prefer `createT(locale)` over partial label maps (missing keys show raw `settings.foo`).
9. Keep frontend locale parsing and native tray locale parsing in sync whenever a locale is added.

## Defaults

| Layer | Default |
|-------|---------|
| `AppSettings.locale` | `"system"` (follow OS; users may lock `en` / `ru` / `zh` / `zh-TW`) |
| `resolveLocale(undefined)` | follow system (unknown OS → `en`) |
| `resolveLocale("system")` | maps Host OS tag / `navigator.language` → `en` \| `ru` \| `zh` \| `zh-TW` |
| Tray unknown locale | English |
| Settings language dropdown | **System** first, then English / Русский / 简体 / 繁體 |
| Compact counts (`formatTokenCount` / `formatLocaleCount`) | `en` / `ru` → K/M/B unless a Russian-specific formatter is added; `zh` → 万/千/百; `zh-TW` → 萬/億. Never hard-code 万 on non-Chinese paths. |

## Follow system

- Preference value stored in `settings.locale` is the string `"system"` (not the resolved catalog id).
- Frontend: `resolveLocaleFromSystem(langTag)` (pure) + Host `__GROK_BOOT_OS_LANG__` + `navigator.languages` + `languagechange` while preference is system.
- Tray / boot: `Locale::from_system` prefers macOS `AppleLanguages` / Windows UI language/locale APIs, then POSIX `LANG` / `LC_*` (ignores `C` / `POSIX`).
- Russian aliases such as `ru-RU`, `ru_RU`, and POSIX `ru_RU.UTF-8` resolve to `ru`.
- One-shot: persisted factory `"en"` → `"system"` (`localeFollowSystemMigrated`). Explicit `ru` / `zh` / `zh-TW` / `system` stay.

## Translation quality

- **English:** primary product language for open source; clear, concise desktop tone.
- **Chinese:** complete sentences, consistent product tone; optional for users who switch locale.
- **Russian:** natural desktop terminology, concise labels, no literal machine-style translation. Keep placeholders (`{name}`, `{n}`, `{path}`, etc.) unchanged and preserve product/CLI identifiers where appropriate.
